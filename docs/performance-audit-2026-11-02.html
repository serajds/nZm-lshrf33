فحص التحميل والطلبات والمؤقتات واعتمادية الاتصال

نقطة البدء: صفحة بنود المشروع، ثم التقارير والحضور وملخص المشروع ولوحة التحكم. أُصلحت أسباب مثبتة في المصدر، مع اختبارات قابلة للتكرار على بيانات مؤقتة معزولة.

حدود النتيجة: لم يُنشر أي تعديل إنتاجي، ولم يُنفذ اختبار ضغط أو انقطاع على الإنتاج، ولم تُستخدم بيانات المشاريع الفعلية كبيانات اختبار. النتائج التالية لا تضمن زمنًا مطلقًا على شبكة المستخدم أو الخادم المنشور.

1. النتيجة مرتبة حسب الأثر

الأثرالتصنيف والدليلالمعالجة
تضاعف استعلامات البنود المرتبطةمثبت: اختبار HTTP مع PostgreSQL حقيقي: 703 استعلامات لعرض 100 بند تشترك في المصدر نفسه.مشاركة وعود ملخص المصدر وقرار الوصول داخل الطلب الواحد فقط؛ النتيجة 10 استعلامات. تبقى المصادر المستقلة متوازية، مع كشف دورات الانتظار بين الفروع.
عمل زائد بعد إعادة الترتيب الخالصمثبت: المسار يعيد قراءة شبكة الربط وحساب ملخصات مجموعات لا تتغير قيمها بالترتيب. كان تحديث الترتيب المجمّع موجودًا أصلًا.تجاوز نشر قيم التقدم عند عدم تغير عضوية المجموعات، مع إبقاء القفل والتحديث المجمّع والتدقيق. نقل بند بين مجموعات ما زال يسلك مسار النشر الأصلي.
تذكير حضور غير صحيح أو مكرر بالموبايلمثبت سلوكيًا بمحاكاة الخدمات الأصلية: القراءة كانت لكل موقع قريب، وفشلها يُفسَّر كعدم حضور، والبداية غير محجوزة أثناء الانتظار.فحص حالة واحد لكل دفعة مواقع، حجز قبل الانتظار، وعدم التذكير للحالة المجهولة. حراسة أجيال المراقبة، وتنظيفها عند الخلفية والخروج، وفصل سجل التنبيه لكل حساب.
تحقق هوية قد ينتظر بلا نهايةمثبت في المصدر واختبار مهلة وهمية: قراءة الهوية وتأكيد 401 بلا حد نهائي.مهلة 12 ثانية تشمل جسم الاستجابة للهوية والتأكيد، و30 ثانية لقراءات الموبايل الأخرى. فشل النقل لا يحذف الجلسة. أُضيفت إعادة تحقق يدوية واضحة، دون إعادة تلقائية للكتابة.
أصفار وقوائم فارغة أو رسائل حفظ مضللةمثبت في الواجهة: الأرقام تُحتسب من قائمة ابتدائية فارغة، وبعض أخطاء الحضور تُرجع نجاحًا فارغًا، وطلب ترتيب فاشل يُوصف بأنه لم يُحفظ حتى إن انقطع الرد بعد التنفيذ.شرطات بدل الأرقام غير المحملة، فصل التحديث الخلفي، إظهار أخطاء التصنيفات والحضور، رسائل بطء/انقطاع، والاحتفاظ بآخر قراءة صحيحة. رسالة الترتيب تقول إن تأكيد الحفظ تعذر وتعيد التحقق من الخادم.
تشغيل مؤقتات في التبويب المخفيمثبت: مؤقتا مزامنة الحضور وفحص PWA بلا سياسة إخفاء واضحة.دورة حياة مشتركة توقف المؤقت عند الإخفاء أو انقطاع الشبكة، وتمنع تداخل الطلبات، وتنفذ تحققًا مستحقًا عند العودة. لم يتغير عداد النظرة السريعة الصحيح.

تفصيل مراحل الترتيب

في العينة الثالثة بعد الإصلاح: انتظار القفل داخل العملية 0.007 ms، وانتظار قفل PostgreSQL 0.10 ms، ومعاملة التحقق والكتابة 3.40 ms، والتدقيق 1.02 ms. نشر المصادر لا يعمل في الترتيب الخالص. قبل الإصلاح سُجل انتظار قفل PostgreSQL تراكمي يقارب 0.36 ms في العينة الثالثة؛ لم يكن هو العامل الغالب محليًا. ليست المراحل تفصيلًا لكل وقت الطلب، ولا يلزم أن تساوي مجموعها مدته.

القياسات متاحة في Server-Timing، وتسجل الطلبات التي تتجاوز ثانية واحدة بأسماء المراحل وأعدادها ومددها فقط، دون SQL أو محتوى المستخدم أو الرموز.

غير مثبت: أن انتظار القفل هو سبب طلبات الإنتاج السابقة التي استغرقت 9125–10972 ms. لم يُعد إنتاجها على الإنتاج، ولم يُخفَ الفرق بين المصدر الحالي والنسخة المنشورة.

4. الحضور والجلسات والمؤقتات والتعافي

  • الموبايل: فحص حضور واحد بدل طلب لكل مشروع قريب، وعدم تداخل الفحص أو بداية المراقبة. نتائج مراقبة قديمة لا تُرسل تنبيهًا بعد إيقافها. لا تنبيه عند فشل القراءة أو غياب المشروع من الاستجابة.
  • الحسابات: بيانات التنبيه مفصولة بالحساب. طابور الحضور يبقى مملوكًا لصاحبه؛ اختبارات الجلسات والطابور الحالية ما زالت ناجحة.
  • المهل: 12 ثانية لكل تحقق هوية أو تأكيد رفض، و30 ثانية لقراءات الموبايل الأخرى. تشمل مهلة القراءة جسم الرد. لا تُطبّق هذه المهلة على كتابة أو رفع صورة قد يحتاج مدة أطول، ولا توجد إعادة كتابة تلقائية مستحدثة.
  • 401 والتجديد: الرد مرتبط بالرمز المستخدم في الطلب. رد متأخر لا يستبدل دخولًا أحدث ولا يخرج حسابًا آخر. 401 غير المؤكد عند انقطاع الشبكة لا يحذف الجلسة؛ و403 لا يطلق آلية انتهاء الجلسة.
  • الويب: إعادة قراءة واحدة محدودة لأخطاء النقل أو الخادم القابلة للتعافي، دون إعادة تلقائية لـ401/403/404 أو الطلب الملغى. سياسات صلاحية البيانات المشتركة بقيت خمس دقائق حيث كانت، ولم تُبطَل كل الاستعلامات دون داعٍ.
  • البحث: إلغاء بحث المصدر المتجاوز فعليًا إلى جانب حراسة النتيجة القديمة؛ وقراءات المجموعات والتصنيفات وسجلات الحضور تستخدم إشارة الإلغاء.
  • الحالات: تمييز التحميل الأولي والتحديث الخلفي والبطء وانقطاع الشبكة وفشل البيانات المساعدة. لا تُعرض نسبة صفر من عدم تحميل القائمة. تعذر قراءة حالة الحضور لا يصبح «غير حاضر» مؤكدًا.
  • الترتيب: منع السحب التالي أثناء الحفظ والتحقق، رسالة انتظار واضحة، وإبطال الكاش المرتبط بالمشروع الذي بدأت فيه العملية. الرد المتأخر لا يعيد بيانات حساب سابق بعد تبديله.
  • الخلفية: توقف مؤقتي الحضور وPWA في التبويب المخفي أو غير المتصل، دون تداخل. مراقبة الموقع في الموبايل تتوقف في الخلفية. دورة حياة عداد النظرة السريعة الصحيحة وتذكير المشروع اليومي لم تُغيّرا.
  • ملفات الواجهة: فُحص المسار الحالي للاستعادة المحدودة من فشل الوحدات؛ بقيت إعادة التحميل المحروسة ومحاولة المستخدم اليدوية دون حلقة إعادة تحميل. لم يظهر Invalid hook call أو خطأ main/خريطة في رحلة المتصفح المعاد تنفيذها؛ الأخطاء التاريخية ليست دليلًا على خلل API حالي.

5. المجمع والخصوصية وحمولة التقارير

إعداد المجمع: min: 0، max: 10، idleTimeoutMillis: 20000، connectionTimeoutMillis: 10000، allowExitOnIdle: true. السعة الافتراضية 10 لم تُرفع لإخفاء تضاعف الاستعلامات. مهلة اكتساب الاتصال تحدد فشلًا واضحًا بدل انتظار المجمع بلا نهاية؛ لم تُضف مهلة واحدة عشوائية لكل الكتابات أو عمليات التصدير الطويلة.

أُثبت بعد انتظار 21 ثانية أن عدد اتصالات المجمع يصل إلى صفر، وأن الاستعلام التالي يعيد إنشاء اتصال وينجح. لأخطاء الاتصالات الخاملة مستمع يمنع انهيار العملية، ويسجل رمز الخطأ دون بيانات اتصال، مع تقليل التكرار إلى سجل واحد لكل 30 ثانية وعداد للأخطاء المكبوتة. أخطاء تنفيذ الطلبات لا تُعاد تسميتها أو إخفاؤها.

الاتصالات السحابية تفرض sslmode=verify-full والتحقق الكامل دون rejectUnauthorized:false، مع الحفاظ على إعداد CA المخصص إن وجد. خدمة PostgreSQL الداخلية المحلية قد لا تدعم TLS؛ لا تُعامل كخادم سحابي عام. لم تُجرَ تجربة حية لشهادة قاعدة الإنتاج أو اختبار فشلها.

لم تتغير مدة JWT أو قواعد الدور الحالي المخزن في قاعدة البيانات أو رؤوس private/no-store للطلبات والملفات المحمية. لم تُنشأ ذاكرة مشتركة بين المستخدمين لبياناتهم أو لقرارات الوصول.

  • اختبار متصفح فعلي بعينات API محاكاة: RTL وسطح المكتب والموبايل وGantt، التنقل والكاش، 403 بلا إعادة تلقائية، إعادة المحاولة اليدوية، انقطاع الشبكة وعودتها مع بقاء البيانات، تأخير 6 ثوانٍ ورسالة البطء والشرطات قبل اكتمال البيانات.
  • 4 نتائج اختبار متصفح للجلسات عبر تبويبات متعددة وتحديث PWA والطابور والردود المتأخرة.
ما لم يُتحقق منه حيًا: جلسة مستخدم حقيقي داخل المشروع 7، شبكة الإنتاج وبدء خدمة Autoscale ومجمعها تحت التزامن، سبب زمن الترتيب التاريخي 9–11 ثانية، PWA المثبت بعد نشر جديد، وسلوك GPS/الخلفية على جهاز Android/iOS فعلي. أداة لقطة المعاينة غير مسجلة الدخول وعرضت صفحة الدخول؛ الواجهة الداخلية فُحصت بمتصفح الاختبار المحاكى فقط. لم تُعطَّل المصادقة من أجل الفحص.

لم تُنفذ عمليات تعديل أو ترحيل على بيانات الأعمال الفعلية ضمن الاختبارات. استُخدمت قاعدة خاصة تُحذف بعد الاختبار، واستجابات متصفح لا تنفذ أي كتابة على API الفعلي. لم يُعَد تصميم النظام ولم تُضف تدرجات لونية.

7. إعادة القياس

المخرجات الخام تُكتب في generated-artifacts/ المستبعد من Git والنشر. لتكرار المقارنة استخدم المرجع السابق لبدء العمل كخط أساس؛ تشغيل الاختبار دون المرجع يتحقق من النسخة الحالية فقط. الأوامر أدناه للمطور الذي يعيد الفحص، ولا تتطلب أسرارًا جديدة.

PERF_BASELINE_REF=321a6d1e38ec859d9b8e90392a06ed9a2acc811c pnpm run test:performance:http
pnpm run test:network-lifecycle
node --test tests/browser-session-cache.test.mjs
ACTIVITIES_VISUAL_URL=http://127.0.0.1:22349 node --test tests/browser-activities-layout.test.mjs
pnpm run build

للمقارنة المنفصلة للواجهة، شغّل اختبار المتصفح مع ACTIVITIES_ISOLATED=1 ACTIVITIES_MEASURE_ONLY=1 PORT=22349، أولًا مع ACTIVITIES_BASELINE_REF بالقيمة السابقة، ثم دونه. أعد العينات في بيئة هادئة قبل تحويل زمن Vite إلى استنتاج أداء.

عند تشخيص طلب بطيء لاحقًا، اربط إصدار الخادم ومدة HTTP ببيانات Server-Timing وسجل المراحل، وافصل انتظار المجمع والقفل والعمل والتدقيق عن زمن تنزيل الواجهة. لا تُنفذ انقطاعًا أو ضغطًا على الإنتاج دون موافقة مستقلة.
