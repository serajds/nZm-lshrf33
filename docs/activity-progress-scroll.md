# ثبات موضع الجدول عند حفظ الإنجاز

## السبب المثبت

نافذة إضافة وتعديل البند مشتركة. عند فتح التعديل من صف بعيد، كانت استعادة التركيز الافتراضية بعد إغلاق النافذة تركز زر «إضافة بند» أعلى الجدول، وليس زر تعديل الصف. هذا يمرر حاوية المحتوى الداخلية نحو الأعلى؛ لم تكن الوثيقة تُحمّل من جديد.

أثبت اختبار متصفح Chromium مع التطبيق الحقيقي وقاعدة PostgreSQL خاصة بالاختبار:
- قبل الإصلاح: موضع التمرير الرأسي 7,874 قبل التعديل ثم 649 بعده، وعدّاد تحميل الوثيقة بقي 1.
- استدعاء التركيز المسبب للقفزة استهدف زر «إضافة بند» دون منع التمرير.
- الزيادة السريعة والتحديد المباشر لم يعيدا تحميل الوثيقة في إعادة الإنتاج الأساسية.

## التغيير

- حفظ زر فتح نافذة تعديل/تحديد الإنجاز، ثم إعادة التركيز إليه مع منع التمرير.
- إذا أزال فلتر الحالة الصف بعد تحديثه، يعود التركيز إلى حاوية القائمة الثابتة دون إعادة الفلتر أو تمريرها لأعلى.
- إبقاء سلوك التركيز الافتراضي لنافذة إضافة بند جديد.
- منع إغلاق نافذة التعديل أثناء إرسال الحفظ، مع إبقاء الأزرار معطلة أثناء الإرسال.
- لا تغيير للحسابات أو طلبات تحديث البيانات أو الصلاحيات أو قيود المصدر المرتبط.

## التحقق

أمر الاختبار:

```sh
NODE_ENV=development ACTIVITY_SCROLL_BROWSER=1 LOG_LEVEL=silent node --import ./scripts/node_modules/tsx/dist/loader.mjs --test tests/activity-progress-scroll.browser.test.mjs
```

يُنشئ الاختبار قاعدة PostgreSQL ومستخدمًا ومشروعًا وبنودًا خاصة به، ويشغل التطبيق الحقيقي خلف خادم واجهة مؤقت، ثم يحذف البيئة المعزولة. لا يتصل بقاعدة مشاريع المستخدم ولا بقاعدة الإنتاج.
