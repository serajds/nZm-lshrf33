# المرحلة 6 — دمج مستهلكي الصور (جزئي)

## صور الملفات وشعارات الشركات

- أُضيف مسار رفع خاص لصور الملفات باستخدام النقل المتوافق مع الحافة
  `text/plain`، ثم خدمة دورة الصورة المشتركة وملف `file_image`.
- يتم التحقق من صلاحية المشروع وصلاحية تبويب الملفات قبل تحليل الجسم، ثم
  التحقق من التوقيع والحجم والأبعاد والبكسلات قبل التخزين.
- يستخدم الطلب مفتاح عميل ثابتًا؛ اختبار HTTP بمخزن تطوير مستقل أثبت أن إعادة
  إرسال الطلب بعد فقد الاستجابة تعيد الملف نفسه دون كائن أو سجل مكرر.
- نُقلت شعارات JPG/PNG/WebP إلى ملف `logo` مع حفظ الشفافية؛ يظل رابط الشعار
  العام قابلًا للعرض كما كان، والحذف الصريح يستهدف المخزن المسجل ولا يحذف
  شعارًا مشتركًا بين شركتين.
- اختبارات HTTP بمخزن التطوير المستقل تحققت من عرض الشعار بلا تسجيل دخول،
  وتخزينه ثم حذفه مع سجل الأصل.
- التخزين الدائم المؤكد شرط نجاح؛ مسار الحذف الصريح يحذف مفاتيح المشتقات من
  المخزن المسجل للصورة فقط، ويزيل سجل الأصل المرجعي. اختُبر ذلك على كائن اصطناعي.
- واجهة الملفات الحالية لا تغيّر اختيار المستخدم أو تصميمها؛ صيغ SVG وGIF تبقى
  على مسارها الانتقالي لأنها ليست مدعومة في محلل الصور النقطية الموحد.

## صور الحضور

- مسارا `text/plain` و`multipart` يتحققان من صلاحية المشروع والعضوية قبل التحليل،
  ثم يستخدمان ملف `attendance` في الخدمة المشتركة والتخزين الدائم.
- جرى نقل إنشاء سجل الحضور والصورة إلى معاملة واحدة؛ إعادة إرسال `clientId`
  تعيد السجل دون تخزين صورة ثانية.
- قراءة الصورة تبقى محمية بصلاحية الحضور، والحذف الصريح يحذف كائن المخزن المسجل
  وسجل الأصل فقط عند عدم وجود سجل آخر يشير إليه.
- اختبر HTTP fixture صيغة الجوال النصية وصيغة الويب متعددة الأجزاء والقراءة
  والحذف وإعادة الإرسال بمخزن التطوير المستقل؛ لم يُختبر هاتف فعلي.

## صور روابط المشاركة

- نُقل رفع الرابط العام إلى دورة الصور الموحدة وملف `report`؛ بقي حد 5 ميغابايت
  وحد الرابط القائم حتى 20 صورة دون تغيير.
- واجهة الرابط ترسل مفتاحًا ثابتًا للصورة ورمز الرابط في عنوان الطلب؛ الحجز
  المشترك متعدد النسخ يحدث قبل تحليل الجسم. العملاء الأقدم الذين يرسلون الرمز
  في الجسم ما زالوا مدعومين، لكن حجزهم يحدث بعد التحليل؛ عند غياب المفتاح
  يستخدم الخادم بصمة محتوى ثابتة لإعادة المحاولة.
- سجل المحاولة وحفظ الأصل والمشتقات وربط التقرير وتحديث العداد تُؤكد معًا؛
  إعادة إرسال الصورة الناجحة تعيد النتيجة دون تخزين مكرر، والترتيب يتبع الحجز
  لا سرعة انتهاء المعالجة.
- اختبار HTTP بمخزن تطوير مستقل تحقّق من حد الحجم، والرفع، وإعادة المحاولة
  دون تكرار، وطلبين متزامنين مع بقاء ترتيب الصور ثابتًا.

## ما بقي

- شعار الشركة بصيغة SVG، وصور GIF، وبقية المداخل المكتشفة لم تنتقل بعد.
- هاتف فعلي وPWA والحافة المنشورة وتجديد الجلسات على أجهزة حقيقية لم تُختبر.
- لا تزال مسارات حذف الصور القديمة ومهام ضغطها لازمة للتوافق التاريخي؛ لم يبدأ
  ترحيل البيانات القديمة أو إيقاف المهام.
- لا تزال مرحلة الحمل المختلط 50 صورة والقياسات الكاملة والمراجعة المستقلة معلقة؛
  لم يحدث أي تغيير إنتاجي.
